# Retro Battle UI (Phase 4) Implementation Plan

**Goal:** The visible layer — link-based rooms, lobby with trainer avatar, lead selection, and a retro Emerald/GBA-style battle screen — wired to `useBattleSocket`.

**Design language:** The dark "Pokédex device" shell we already have wraps everything; the *battle scene itself* uses a classic GBA look — opponent top-right + player bottom-left on a two-tone field, light HP boxes with dark borders and pixel text, a bottom text box that narrates the turn. Reuse Press Start 2P (`.readout`), `TYPE_COLORS`, `TypeBadge`, and `next/image` with the pixel `frontSprite`/`backSprite` (host already allowed).

**Verification:** This phase is verified by RUNNING it — boot `pnpm dev` (custom Socket.IO server) and drive TWO browser tabs through a full battle with Playwright, screenshotting and iterating on the look. Only `describeEvent` (event → localized log lines) is unit-tested.

## Data (from Phase 1–3b, all built)

- Hook: `useBattleSocket(roomId)` → `{ view, slot, events, error, send }`. `send(msg: ClientMessage)`.
- `view: RoomView` = `{ roomId, phase, you, players, yourTeam, battle, awaiting, winnerSlot }`; `phase` ∈ waiting|lobby|teaming|battle|finished.
- `ClientMessage` = setProfile{nickname,gender} | chooseLead{teamIndex} | action{action} | rematch.
- `events` = latest turn's `BattleEvent[]` (animate, then replaced next turn).

## Screen behavior (drive off `view.phase`)

- **waiting** → show the room link + "Waiting for a challenger…"; also render the lobby form (so P1 can fill profile while waiting). Actually: render lobby form in `waiting`+`lobby` (both players fill profile as soon as they connect).
- **lobby** → `LobbyForm`; once you submit, show "waiting for opponent" until phase advances.
- **teaming** → `TeamSelect` (your 3, pick lead); waiting state after you pick.
- **battle** → `BattleScene` + `ActionMenu` (enabled only when awaited) + `BattleLog`. On a forced switch (`awaiting` = you and `battle.forcedSwitch[you]`), the menu shows only switch targets.
- **finished** → `ResultScreen` (win/lose vs `winnerSlot`/`you`) + Rematch.

## i18n `battle` dictionary shape (add to Dictionary + en + es)

```ts
battle: {
  title: string; create: string; shareHint: string; copy: string; copied: string;
  waitingOpponent: string; nickname: string; nicknamePlaceholder: string;
  gender: { male: string; female: string }; ready: string;
  chooseLead: string; yourTeam: string; waitingLead: string; vs: string; lv: string;
  fight: string; switchLabel: string; run: string; runConfirm: string;
  yourTurn: string; opponentTurn: string; noPp: string; fainted: string;
  status: Record<StatusCondition, string>;
  result: { victory: string; defeat: string; rematch: string; opponentLeft: string };
  log: {
    used: (mon: string, move: string) => string;
    superEffective: string; notVery: string; immune: (mon: string) => string; crit: string;
    miss: (mon: string) => string; faint: (mon: string) => string;
    statusInflict: (mon: string, status: string) => string;
    statusHurt: (mon: string, status: string) => string;
    cantMove: (mon: string, status: string) => string;
    wake: (mon: string) => string;
    switch: (to: string) => string;
    win: (nick: string) => string;
  };
}
```

## Notes

- Keep the scene responsive; sprites `image-rendering: pixelated` for the retro crunch.
- `describeEvent` is the only unit-tested unit; screens are verified by driving two tabs.
- Forfeit/RUN sends nothing engine-level (no "flee" action exists); implement RUN as a disconnect/leave → opponent wins by forfeit (navigate away or emit a leave). Simplest: RUN = `router.push('/')` which disconnects the socket → server forfeits.
